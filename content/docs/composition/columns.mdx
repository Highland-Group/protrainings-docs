### What the columns block is

A container block holding a single flat array of cells. Each cell is one block carrying its own `size` — `full`, `half`, `third`, `quarter`. There is no rows array, no columns array, and no nested Columns block. Rows are emergent: cells lay out left to right across a twelve-column grid and wrap when the next one doesn't fit.

Structurally this is the Payload website template's Content block with the `richText` field replaced by the block itself. `size` is a shared field spread into every cell-class block rather than a property of a wrapper, which is what keeps reordering flat — a cell can be dragged anywhere in the array, including across what renders as a row boundary.

**Columns is always margin-bound.** It lays out inside the content measure at every size, including `full`. Breaking the measure — edge-to-edge media, full-bleed color fields — is what Brand Layouts do and Columns does not. That is the boundary between the two classes: bleed, not width. A full-measure Rich Text block and a full-bleed hero are not the same output, so the two classes never produce the same result by different routes.

`full` is available per block type, not universally. Content-shaped blocks take it — Rich Text, Image / Media, CTA, Form. Card-shaped blocks do not: a full-measure Statistic Card or Course Card is a composition nobody needs the option to build. Because `size` is a shared field, the options array can differ per block, so this is enforced declaratively at the schema rather than through review.

<Callout type="info">
Additional column widths may be added dependent on brand needs. 
</Callout>

#### Partial rows

Rows do not have to resolve to twelve. A lone `third` is a third-width block with negative space beside it, and that is a legitimate composition rather than an error state — it will also be the honest result for a number of source pages during migration.

Leftover space flows to the end of the row. Cells align to start; nothing centers, stretches, or redistributes to close the gap. There is no save-time validation on row totals and no auto-normalization of sizes. Both would intervene on intermediate states an editor is still composing, and normalization in particular edits intent in a way that can't be diagnosed from the admin.

#### Stacking

A cell holds one block. That constraint produces the rule:

> **Columns place peers. Anything with internal hierarchy is a Brand Layout.**

The pressure this creates is absorbed in two places. The Rich Text block handles heading-plus-body in a single cell, which covers most stacking cases. Compositions with real internal hierarchy — a headline governing a set of images, for instance — are designed as Brand Layouts rather than assembled.

## Planned for v1


| Blocks Available Inside Cells | Design Notes |
| --- | --- |
| **Rich Text** | Styles defined by tokens, handles H2 - body copy |
| **Statistic Card** | Visualized statistic or data callout. |
| **Course Card** | Displays a selected course. Brand design scoped to be nested. |
| **Poster** | Stylized card that composes an image or graphic with typography. |
| **Media** | Displays an image or graphic from the media library. |
| **Icon List** | icon-paired items as a stylized alternative to unordered lists. |
| **Call to Action** | A poster style Call To Action. Brand Design scoped to be nested. |
| **Form** | A stylized form scoped to be nested. |
